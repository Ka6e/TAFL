# Семантика языка Glacier

---

## Области видимости

В языке Glacier используются **лексические области видимости**.

Область видимости определяется структурой программы и не зависит от порядка вызова функций.

### Конструкции, создающие новую область видимости

Новая область видимости создаётся следующими конструкциями:

* тело функции (`func`)
* блок кода `{ ... }`
* тело класса
* блок `case` внутри `match`

Переменные, объявленные внутри области видимости, недоступны за её пределами.

Локальные переменные уничтожаются при выходе из соответствующей области видимости.

---

## Уникальность имён

### Пространства имён

В языке Glacier используется **единое пространство имён** для:

* переменных
* функций
* классов
* перечислений (enum)

Допускается совпадение имён разных сущностей, если они находятся в разных областях видимости.

Пример допустимого кода:

```glacier
func Foo() {}
class Foo {}
```

### Сокрытие имён

Разрешено сокрытие (shadowing) имён:

* переменная может скрывать переменную внешней области видимости
* локальная переменная может скрывать параметр функции
* пользовательская переменная или функция может скрывать встроенную функцию

Сокрытие встроенных типов данных **не допускается**.

## Переменные и присваивание

### let и var

* `let` объявляет **неизменяемую переменную**
* `var` объявляет **изменяемую переменную**

Переменная, объявленная с помощью `let`, должна быть инициализирована при объявлении.

Попытка присвоить новое значение переменной `let` является семантической ошибкой.

### Инициализация

* Переменная, объявленная без инициализатора, считается **неинициализированной**
* Обращение к неинициализированной переменной запрещено и является семантической ошибкой

### Присваивание

В левой части оператора присваивания может находиться только идентификатор переменной.

Присваивание допустимо только для переменных, объявленных с помощью `var`.

## Параметры функций

### Передача параметров

Параметры функций передаются **по значению**.

Изменение значения параметра внутри функции не влияет на аргумент, переданный при вызове.

### Параметры и область видимости

* Параметры функции являются локальными переменными функции
* Параметр может быть скрыт локальной переменной

### Вызов функций

* Число фактических параметров должно совпадать с числом формальных параметров
* Несовпадение количества аргументов является ошибкой времени компиляции
* Аргументы вычисляются **слева направо**

### return

* Функция с возвращаемым типом `void` может завершаться без оператора `return`
* Функция с другим типом возвращаемого значения должна завершаться оператором `return`

## Рекурсия

Язык Glacier поддерживает:

* прямую рекурсию
* взаимную рекурсию

Функции считаются объявленными в пределах всего модуля, что позволяет вызывать их до текстуального определения.

---

## Булева семантика

В языке Glacier используется **гибридная булева семантика**:

* тип `bool` существует как отдельный встроенный тип
* в условиях (`if`, `while`) допускаются выражения типа `bool` и `int`
* значение `0` трактуется как `false`
* любое ненулевое числовое значение трактуется как `true`

Логические операторы `&&`, `||`, `!` возвращают значения типа `bool`.

Операторы `&&` и `||` используют вычисление с коротким замыканием (short-circuit).

## Ветвления

### if / else

* Если условие истинно — выполняется блок после `then`
* Если условие ложно — выполняется блок после `else` (если он присутствует)

### match

Оператор `match` выполняет сопоставление значения с шаблонами (`case`).

Семантика `match`:

* выполняется ровно один подходящий `case`
* проваливание между `case` отсутствует
* порядок `case` имеет значение
* `_` обозначает шаблон по умолчанию (wildcard)

Если ни один `case` не подошёл и отсутствует `_`, поведение считается ошибкой времени выполнения.

---

## Циклы

### while

Цикл `while` выполняется, пока условие истинно.

### for

Цикл `for` выполняется в следующем порядке:

1. выполняется инициализация
2. проверяется условие
3. выполняется тело цикла
4. выполняется выражение шага

Цикл завершается, когда условие становится ложным.

### break и continue

* `break` завершает выполнение ближайшего цикла
* `continue` переходит к следующей итерации ближайшего цикла

Использование `break` и `continue` вне циклов является семантической ошибкой.

---

## Прочие правила

* Обращение к несуществующему идентификатору является ошибкой времени компиляции
* Попытка изменить неизменяемую переменную (`let`) является семантической ошибкой
* Все семантические ошибки должны быть обнаружены до выполнения программы, если это возможно
